# DeepSeek 娘动态动作

0.5.0 为全部 19 种表情增加逐帧循环。原来的静态立绘保留用于头像图标和动作资源加载失败时的后备显示。每个动作由四张不同绘画帧组成，各帧有独立停留时间，避免所有表情以同一个频率运动。

| 表情 | 动作 |
| --- | --- |
| 待机、眨眼 | 挥手、眼睛开合 |
| 开心、害羞、得意 | 笑起来、手指小动作、轻轻点头 |
| 生气、委屈、震惊、疑问 | 鼓脸轻哼、含泪眨眼、小惊吓、歪头 |
| 比心、加油、庆祝 | 比心眨眼、挥拳、举手欢呼 |
| 思考、工作、学习 | 托腮、敲键盘、翻书 |
| 无聊、吃白饭 | 托脸叹气、夹饭入口与咀嚼 |
| 困困、睡觉 | 打哈欠、闭眼轻呼吸 |

## 使用

表情页的预览、桌面角色和对话顶部头像都能播放。自动跟随任务的规则不变；手动选定表情会固定动作类型并循环播放。“让她动起来”开关可暂停全部角色动作与装饰动画，设置会保存。开启系统“减少动态效果”时定格第一帧。隐藏、最小化窗口或滚出视野的预览会暂停，重新可见时继续。

## 资源与播放

`public/characters/deepseek-girl/animations/` 中每个同名 PNG 是严格按左上、右上、左下、右下读取的 2 × 2 帧图。19 张源图由内置 ImageGen 编辑生成，保留原生 alpha；完整提示词及各张路径见 [animation-prompts.json](animation-prompts.json)。它们是独立原始资源，不覆盖静态立绘。

`shared/motions.mjs` 定义每个动作的停留时间。`src/Motion.tsx` 解码资源、裁切并用 Web Animations 播放，不需要逐帧 React 状态更新。`registration.json` 记录按 alpha 分析得到的主体边界与脚底锚点，用于排除相邻格的边缘碎片和修正位置偏移；源 PNG 不变。0.7.0 起还分析全部静态图，记录主体顶部、可见身高与脚底。`shared/character-layout.mjs` 将所有静态图和动作帧缩放/平移到相同 1000 × 1200 坐标系（主体高 1100、脚底 y=1160），因此跨表情、跨静态/动态都保持一致大小。分析裁切时扩展格子边缘以纳入越过分格线的鲸尾，仍以最大连通主体的带余量凸包排除邻帧边角碎片。裁切只绘制当前格，避免其他帧漏出。未在视野中的动作延迟解码；图片失败时显示对应静态立绘，任务文字照常更新。

Electron 的原生 show/hide/minimize/restore 通过受限 IPC 通知可见性，另结合页面 visibility 和 IntersectionObserver；透明窗口的可见状态不只依赖浏览器判断。动态开关和减少动态效果也会停止星星等 CSS 动画。

## 维护与验证

替换动作图后先 `npm run build`，再运行 `npm run register:motion` 更新帧边界，最后重新构建。此步骤只分析透明通道并生成 JSON，不修改原图。

`npm test` 校验所有表情都有完整循环、时序合法、PNG 分辨率与透明通道，以及全部 95 个姿态的统一身高、脚底与动作矩阵。构建后 `npm run test:motion` 在隔离 Electron 应用中逐个检查四帧像素确有区别、播放后的画面实际变化、透明背景、系统减少动态效果、开关暂停及隐藏后恢复。`npm run test:ui` 验证任务联动、表情页开关与预览、设置持久化和原有对话流程。所有测试使用本机协议夹具，不调用模型。
