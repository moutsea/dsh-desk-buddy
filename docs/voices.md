# 提示语音包

应用使用 `qwen-audio-3.1-tts-flash` 提前生成的中文短句。音频保存在 `public/voices/`，Vite 会原样复制到 `dist/voices/`，并由现有 Electron 打包配置包含。用户无需配置 API Key；应用运行时只加载本地 WAV 文件。

## 重新生成

在开发环境中提供 `DASHSCOPE_API_KEY` 后运行：

```sh
npm run generate:voices
```

生成脚本调用北京地域的 DashScope `audio/tts/SpeechSynthesizer` 接口，参数见 [官方 HTTP API](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-http-api)。该命令会产生语音合成用量，应用播放不会。

原始响应音频和非敏感参数缓存到 Git 忽略的 `artifacts/tts-source/`。相同模型和参数会复用缓存，缺失或参数变化时才重新调用。初次生成时若存在前三种已试听音频及匹配的清单，也会复用它们。需要重新生成某一条相同参数的表演时，移除对应的缓存 WAV 和 JSON；对于沿用的试听，还需移除其 `artifacts/tts-preview/` 缓存。

输出为 24 kHz、单声道、16-bit PCM WAV。脚本修复服务返回的流式 WAV 长度占位值，按 RMS 统一音量并限制峰值，闲置和入睡音量更低，首尾加入 5 ms 淡入淡出。

## 播放与设置

`sounds.voice` 保存所选音色 ID；旧配置或未知音色回退为「俏皮少女」，其他开关和音量继续保留。IPC 只接受目录内的音色 ID。

音频按需加载、解码和缓存。切换声线会中止旧声音及尚未播放的旧请求；静音、音量归零和单项关闭会中止对应播放。在非零音量之间调节或修改无关场景开关，会保留仍然允许播放的请求，按最新音量播放。试听声线独立于 13 个场景开关，仍遵守总开关及音量。

连点小脾气与自动生气反应同步：1.8 秒内点 5 次触发，每次持续生气只说一次，冷却 6 秒。生气语音会替换普通摸摸回应，但不会打断任务完成、待回应或失败提醒。固定表情、工作状态等遮盖互动反应时不触发；加载期间反应失效也不补播。`sounds.angry` 可独立控制，旧配置尚无此开关时继承 `sounds.pet`，保留已静音的触摸偏好。

开工、入睡、搬家和恢复连接默认关闭，其他场景默认开启。开始任务和任务出错由接受的实时事件触发，历史记录和运行状态快照不触发；任务取消、工具调用暂时失败及子代理事件不单独发声。审批或提问按 RPC 去重，同一服务重连后不重复提醒已见事项。任务结束会取消开工回应，事项解决会取消待回应提醒；连接改变后，这些场景尚未播放和正在播放的提醒都会取消，过期事件不补播。

悬停 8 秒的害羞回应冷却 1 分钟；点击自然入睡的桌宠会叫醒，冷却 1 分钟；没有互动至少 10 分钟后的点击优先欢迎回来，冷却 10 分钟，避免与叫醒叠播。入睡回应只在自然进入睡眠时触发，冷却 5 分钟；固定睡眠表情和悬停不触发。拖动必须实际改变位置并正常放下，冷却 30 秒，取消或回到原点不发声。连接提醒只对观察到的至少 10 秒断线、随后稳定连接 3 秒触发，冷却 1 分钟；初次连接、换服务和短暂闪断不提醒。隐藏、静音或关闭时错过的场景不补播。新增害羞、叫醒、欢迎开关在旧配置中继承摸摸开关，保留原有静音偏好。

摸摸、闲置、开始任务、任务完成、需要回应和任务出错各有三句：首次播放保留原台词，之后随机选择与上次不同的一句。只有成功播放才推进选择，同一场景共享开关和冷却；设置试听与自动回应分别记录。工作提醒沿用事件去重、过期取消和优先级规则，同一次任务事件只选择一句；变换台词不会增加提醒频率。

读取、解码及唤醒音频设备最多等待 1 秒。失败或超时后，设置页显示错误，可再次试听重试；未完成的音频读取会取消并移出缓存，已成功解码的音频继续复用。迟到的旧请求不会播放或覆盖重试缓存。

待回应和出错提醒在加载和播放期间优先于任务完成，任务完成优先于开工、小脾气、摸摸、闲置和试听。同一批事件优先待回应，同级自动请求合并，避免叠音和排队补播。自动闲置语音在加载结束后再次检查状态；打开面板、开始工作、隐藏、睡眠或重新互动会取消旧的闲置请求及正在播放的闲置招呼，恢复空闲后不会补播。设置里的手动试听不受自动闲置条件限制。

`npm test` 检查设置迁移、音色白名单及全部资源的完整性、波形和来源记录；`npm run build && npm run test:sound` 使用真实 Electron 窗口验证本地解码、音量、播放策略、声线选择与重启保存。
