# 提示语音包

应用使用 `qwen-audio-3.1-tts-flash` 提前生成的中文短句。音频保存在 `public/voices/`，Vite 会原样复制到 `dist/voices/`，并由现有 Electron 打包配置包含。用户无需配置 API Key；应用运行时只加载本地 WAV 文件。

音色来自 [Qwen-Audio-TTS 官方音色列表](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-voice-list)。风格是选音与合成的方向，实际效果可在设置中试听。

界面使用描述听感的名称，来源名称用于开发时追溯。显示名称与保存的音色 ID 独立，改名不影响已有选择或音频文件；合成风格保持独立，避免文案修改触发重新生成。

每种声线均包含：

- `pet.wav`：「嗯？嘿嘿。」
- `completion.wav`：「做好啦！」
- `idle.wav`：「陪我玩一会儿嘛。」
- `preview.wav`：「嗯？嘿嘿，做好啦！」

目录和台词由 `shared/voices.mjs` 定义。`public/voices/manifest.json` 记录每个文件的台词、生成指令、请求 ID、时长与 SHA-256；其中不包含凭证或临时下载链接。前三种声线的试听沿用首次生成的表演，保留原始指令记录。

## 重新生成

在开发环境中提供 `DASHSCOPE_API_KEY` 后运行：

```sh
npm run generate:voices
```

生成脚本调用北京地域的 DashScope `audio/tts/SpeechSynthesizer` 接口，参数见 [官方 HTTP API](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-http-api)。该命令会产生语音合成用量，应用播放不会。

原始响应音频和非敏感参数缓存到 Git 忽略的 `artifacts/tts-source/`。相同模型和参数会复用缓存，缺失或参数变化时才重新调用。初次生成时若存在前三种已试听音频及匹配的清单，也会复用它们。需要重新生成某一条相同参数的表演时，移除对应的缓存 WAV 和 JSON；对于沿用的试听，还需移除其 `artifacts/tts-preview/` 缓存。

输出为 24 kHz、单声道、16-bit PCM WAV。脚本修复服务返回的流式 WAV 长度占位值，按 RMS 统一音量并限制峰值，闲置音量更低，首尾加入 5 ms 淡入淡出。

## 播放与设置

`sounds.voice` 保存所选音色 ID；旧配置或未知音色回退为「俏皮少女」，其他开关和音量继续保留。IPC 只接受目录内的音色 ID。

音频按需加载、解码和缓存。切换声线会中止旧声音及尚未播放的旧请求；静音、音量归零和单项关闭会中止对应播放。在非零音量之间调节或修改无关场景开关，会保留仍然允许播放的请求，按最新音量播放。试听声线独立于三个场景开关，仍遵守总开关及音量。

读取、解码及唤醒音频设备最多等待 1 秒。失败或超时后，设置页显示错误，可再次试听重试；未完成的音频读取会取消并移出缓存，已成功解码的音频继续复用。迟到的旧请求不会播放或覆盖重试缓存。

任务完成提醒在加载和播放期间优先于摸摸、闲置和试听请求，重复的完成请求会合并。自动闲置语音在加载结束后再次检查状态；打开面板、开始工作、隐藏、睡眠或重新互动会取消旧的闲置请求及正在播放的闲置招呼，恢复空闲后不会补播。设置里的手动试听不受自动闲置条件限制。

`npm test` 检查设置迁移、音色白名单及全部资源的完整性、波形和来源记录；`npm run build && npm run test:sound` 使用真实 Electron 窗口验证本地解码、音量、播放策略、声线选择与重启保存。
