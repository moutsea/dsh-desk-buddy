# Codex 接入（实验功能）

从 0.17.0 起，桌宠可以同时连接 DSH 和 Codex。DSH 插件管理的实例保留所属 DSH，也可另外连接 Codex。Codex 接入目前为实验功能，支持范围和操作方式如下。

## 启动

已在 macOS Apple Silicon、Codex CLI `0.154.0` 上联调。先安装并登录 Codex，启动一个本机共享服务：

```sh
codex app-server --listen ws://127.0.0.1:4500
```

另开终端，将 Codex 终端窗口接到相同服务：

```sh
codex --remote ws://127.0.0.1:4500
```

安装或更新至 0.17.0 及以上版本后，从 DSH 启动桌宠。源码开发时也可在项目目录独立运行：

```sh
npm run build
npm start
```

打开桌宠 **设置 → 会话服务 → Codex（共享 App Server）**，地址填 `ws://127.0.0.1:4500`，点击连接；这不会断开已连接的 DSH。设置会分别显示两个平台的连接状态，也可单独断开 Codex。支持 IPv4 / IPv6 回环地址，不接受远程地址或 URL 内的凭证。

想与平常的桌宠配置隔离，可使用单独目录：

```sh
DEEPSEEK_GIRL_DATA_DIR=/tmp/dsg-codex-preview npm start
```

## 区分平台

两个平台同时连接时，点击「新建会话」会先选择 **DSH** 或 **Codex**。只有一个平台在线时直接在该平台创建；空白对话也可以通过「新会话平台」指定第一条消息的目标。

会话列表和进度气泡带平台标识。DSH 对话框保留浅色，Codex 对话框及进度气泡使用黑灰色。两边已出现的任务气泡在结束后继续保留，可通过右上角 × 关闭显示；不会停止任务，下次新任务会重新出现。外部只读会话不自动触发气泡。切换会话时，草稿、Token 用量、审批和操作跟随各自的会话；断开或重连一个平台不会清除另一个平台的数据。重启会恢复之前启用的连接。

## 能力与边界

- 列出当前 Codex 数据目录中未归档的历史会话，包括桌面端、CLI 和 App Server 来源。外部会话标明「仅查看」，打开后每 3 秒读取一次已保存内容；支持历史分页，不会自动恢复或接管任务。
- 跟随同一服务里已加载的普通会话：流式回复、工具调用、后台任务、状态气泡、完成及失败语音。
- 在桌宠新建会话、发送消息、补充正在执行的任务、取消当前轮次。执行中补充使用 Codex `turn/steer`，会立即送入当前任务，与 DSH 排队语义不同。
- 命令和文件审批支持允许一次、会话内允许、拒绝、停止；命令规则和网络规则只展示服务实际提供的选项，保存前展示规则内容。支持额外权限请求与选项/文字问答。
- 专门的 MCP 登录、设备验证等请求显示“在 Codex 原窗口处理”，不会自动代答。其他客户端完成审批后，桌宠清除对应提示。
- Token、缓存命中率和上下文使用 Codex 实际上报。缓存输入已包含在输入总量中，推理输出已包含在输出总量中。尚未上报、重连后尚未重新上报的指标显示 `—`，不推算生成速度，也不展示 DeepSeek 余额。
- 断线按指数退避重新连接并订阅，等待时间带抖动、上限 30 秒，连通后重置；设置页显示下次重试间隔。手动断开会停止重试。首次连接失败保留错误，等待用户重新连接；发送、取消和审批不会自动重试。发送超时保留草稿，请检查历史后决定是否重发。

**连接共享服务不等于连接已有 Codex 桌面窗口。** 同一数据目录中的会话内容可只读查看，但桌面窗口和独立 CLI 的实时运行状态、发送、取消和审批仍未接入；这些操作需要在原窗口完成。要从桌宠完整操作，需让会话运行于相同 App Server，例如在连接此服务的 Codex 终端中恢复。不同 `CODEX_HOME`、云端和已归档会话不在当前列表中；其他客户端的空草稿在首条消息落盘后出现。

桌宠不启动、停止或重启 Codex 服务。退出只关闭自身连接；如果需要任务持续运行，请保留 Codex 终端客户端，共享服务会自行管理无人订阅的会话。

WebSocket 接口目前是 Codex 官方的实验接口；本次适配包含旧式历史存储的读取回退。协议与运行方式参考 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

切换同一平台的地址时，原连接、会话和待审批事项保留到新连接及事件流全部就绪；切换失败继续使用原地址，不改写保存的设置。历史轮次补读每个平台最多并发 4 个请求，慢查询期间定时刷新不会再启动一轮补读。

## 验证

```sh
npm test
npm run build
npm run test:codex
npm run test:platforms
```

`test:packaged` 也包含 `codex` 和 `platforms`，由 Windows / macOS CI 运行实际打包程序和离线假主机。上面的测试不调用模型。真实双客户端联调会在临时目录创建专用会话，调用已登录的 Codex，产生少量模型用量；覆盖回复、流式输出、用量、命令审批和跨客户端取消：

```sh
DSG_CODEX_ENDPOINT=ws://127.0.0.1:4500 npm run test:codex:live
```

测试只允许预定的无文件修改命令（Python 等待并打印数字），并主动取消测试轮次。结果写入忽略提交的 `artifacts/codex-live-report.json`。不会选中或操作已有用户任务。
